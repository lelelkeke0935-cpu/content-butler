# 內容管家

感謝你使用內容管家。本工具協助選物店編輯整理創作者素材，產出可人工審核的文章與上架包。適合需要介紹插畫、文具與設計小物的店家使用。

本專案是 2026-10-04 DevDay Exchange Community Hack Day: Taipei 當天 13:00 後從零做的。

## 怎麼啟動

需要 Node.js 24，不用安裝套件。在專案資料夾執行：

```sh
node server.mjs
```

開啟 http://127.0.0.1:8990 。服務只在本機開放。

一般生成使用本機 Codex CLI 與 OpenAI 模型，不使用 API key。請先完成 Codex CLI 登入。模型依本機 Codex 設定，程式不指定模型版本。可透過 `CODEX_BIN` 指定執行檔，透過 `PORT` 指定連接埠。

離線示範可使用：

```sh
MOCK_AI=1 node server.mjs
```

此模式回傳固定的虛構資料，不會依新素材改寫，也不會啟動 Codex。品牌網站仍由獨立的抓取功能處理；無法連線時會回報讀取失敗。示範中的霧栗、慢郵小屋、口袋苔與紙岸小舖皆為虛構設定。

## 生成前的行銷設定

素材輸入區可選擇「認識創作者／新品上市／送禮推薦／到店參觀」，預設認識創作者。受眾、場合與客人購買預算皆可選填；預算請註明幣別及單位，例如「每份 NT$500–1,000」，不是廣告費或已確認售價。

四個 AI 階段都會收到同一份行銷設定，用來調整關鍵字、訪談缺口、文章重點與行動呼籲。設定不作為已查證事實；未填資訊不推定，商品價格、上市日期、實體店址與營業時間仍需來源支持。

開始生產後會顯示本次設定，生成期間暫停編輯。修改設定後需再次按「開始生產」；舊結果仍可閱讀，但不能用新設定單獨重跑舊階段。每種設定有獨立快取。離線示範（包含 `?mock=1`）仍回傳固定虛構資料，不會依行銷設定改寫。

## 五個階段

1. 關鍵字：辨認主角，整理主關鍵字、次關鍵字與客人會問 AI 的話。
2. 訪綱：整理素材事實、原文依據與待確認資訊，產出訪談題目。
3. 架構：安排文章標題、開頭回答、四段重點與常見問答。
4. 文案：依素材撰寫文章。缺少事實時保留「【待訪談補充：…】」。
5. 上架包：提供 HTML、Markdown、結構化資料與八項檢查，建議下一個週二台北時間上午十點上架。

前四階段使用 AI；第五階段採固定規則。上架包仍需人工核對，不代表已發佈。

## 誠實標示來源

- 即時生成：本次透過 Codex CLI 產生，顯示本次耗時。
- 已保存：沿用相同輸入的快取，保留原本生成時間與耗時。
- 示範資料：固定的虛構內容；即使命中快取，仍須優先標示示範資料。

快取保存在 `data/cache.json`。重新生成會略過快取並覆寫相同輸入的結果。示範結果與真正 AI 結果不混用。

素材支援貼文字、txt、md、docx，上限 25 MB。docx 轉文字需要 macOS 內建的 textutil。素材會清除重複相鄰行、多餘空行與指定方向控制字元。AI 最多使用前 6000 字。

「載入示範素材」若找到 `materials/` 的 txt，會優先讀第一份並標示為私人素材；沒有才讀虛構範例。啟用真實生成時，素材與品牌資料會經 Codex CLI 交給 OpenAI 模型處理，請先確認素材可供使用。

## 自動檢查

```sh
node scripts/smoke.mjs
node scripts/marketing-smoke.mjs
```

測試在暫存副本以 `MOCK_AI=1 PORT=8991` 啟動。品牌抓取使用本機測試頁，不連外網、不啟動真正的 Codex。檢查全部 API、快取、來源欄位、八項檢查、文件上傳及錯誤回應，最後印出 PASS 或 FAIL 並關閉測試伺服器。測試時請保留 8991 埠可用。

行銷設定測試使用暫存副本與替身 Codex，檢查四階段提示詞傳遞、設定驗證、預設值與快取隔離，不呼叫真正 AI。

## 今天不做什麼

今天不連接 Shopify 後台自動發佈與排程，不做帳號登入、多品牌管理或資料庫。輸出的文字仍需訪談補齊與人工確認。

有待補內容時，請先完成訪談，再重新整理素材與文章。
